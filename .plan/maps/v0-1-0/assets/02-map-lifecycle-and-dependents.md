# Map lifecycle and what depends on map shape

Source: references/decompiled/sts2-il.txt and sts2.txt for game v0.107.1, plus references/decompiled/fight-all-choices.txt. Everything below was read from IL or the call lists unless it carries the tag [inferred]. Type names drop the `MegaCrit.Sts2.Core.` prefix.

## 1. When the map is created and when AfterMapGenerated fires

`RunManager.GenerateMap` is the only place a live act map is built and assigned. It is called from three places: `RunManager+<SetActInternal>d__197` (every new act, fresh run included), `Nodes.NGame+<LoadRun>d__143` (loading a save), and `NMultiplayerTest+<RunReplay>d__33` (debug replay). Its state machine is `RunManager+<GenerateMap>d__177.MoveNext`. In order:

1. `MapSelectionSynchronizer.BeforeMapGenerated`. This bumps `MapGenerationCount` and cancels stale multiplayer votes.
2. It checks `RunManager.SavedMapsToLoad` for an entry keyed by `RunState.CurrentActIndex`.
3. Saved branch: `new SavedActMap(serializable)`, remove that key (set the dictionary to null once empty), then `Hook.ModifyGeneratedMapLate`, then `Hook.AfterMapGenerated`.
4. Fresh branch: `ActModel.CreateMap(runState, false)` (which is just `StandardActMap.CreateFor`), then `Hook.ModifyGeneratedMap`, then `Hook.AfterMapGenerated`. Only the fresh branch then runs `if (!StartedWithNeow && CurrentActIndex == 0) StartingMapPoint.PointType = Monster`. The saved branch skips it because the saved start point already carries its type.
5. Both branches then run `RunState.set_Map(map)`, then `RunState.RemoveStaleVisitedMapCoords(map)`, then `NMapScreen.SetMap(map, rng seed, true)` if the screen instance exists.

Answers to the ticket's direct questions:

- `Hook.AfterMapGenerated` fires once per `GenerateMap` call on both branches. It does fire again on a load from save. A mod handler must treat the incoming map as possibly already converted.
- `Hook.ModifyGeneratedMap` is `foreach listener: map = listener.ModifyGeneratedMap(...)` and then ends with `return ModifyGeneratedMapLate(...)`. So on the fresh branch both Early and Late hooks run, Early first. On the saved branch only `ModifyGeneratedMapLate` runs. Early hooks therefore build or replace the map once, and Late hooks decorate the map again on every load.
- `AfterMapGenerated` returns a Task and takes the map by value, so it cannot swap the map reference. `set_Map` happens after it, using the local that `ModifyGeneratedMap` or `SavedActMap` produced. A handler there can only mutate the existing map in place. The reference mod (FightAllChoices) does exactly this with a Harmony postfix on `Hook.AfterMapGenerated` that chains `RewriteAfter` onto `__result` and calls `LayerMapLogic.RewriteTopology`. It reaches into `ActMap.startMapPoints` and `NMapScreen._mapPointDictionary` by reflection.
- Replacing the map object is possible only inside `ModifyGeneratedMap` or `ModifyGeneratedMapLate`, or by patching `ActModel.CreateMap` / `StandardActMap.CreateFor`. The game already does this: `GoldenCompass`, `SpoilsMap` and `BigGameHunter` return brand new map objects from `ModifyGeneratedMap`.
- The only `AfterMapGenerated` override in the base game is `Models.Cards.SpoilsMap` (it calls `HasPoint(SpoilsCoord)` then `GetPoint(...).AddQuest`). The virtual is declared on `AbstractModel`. (The dump attributes the declaration to `UnknownIntent`; that is a dump quirk, `AbstractModel` begins at line 45492 of sts2.txt.)

## 2. Save and load

- `RunManager.ToSave` writes only the current act's map: for the act at `CurrentActIndex` it sets `SerializableActModel.SavedMap = SerializableActMap.FromActMap(RunState.Map)`. Other acts have no saved map. It also writes `VisitedMapCoords` and `MapPointHistory`.
- `SerializableActMap.FromActMap` stores: `Points` (every non-null cell of `Grid` via `GetAllMapPoints`), `BossPoint`, `SecondBossPoint` (or null), `StartingPoint`, `StartMapPointCoords` (from the protected `startMapPoints` set, only when non-empty), `GridWidth` (`GetColumnCount`), `GridHeight` (`GetRowCount`). Each `SerializableMapPoint` has coord, point type, `CanBeModified` and child coords. Parents are rebuilt from child coords.
- `SavedActMap..ctor` allocates `Grid[GridWidth, GridHeight]`, places `Points` at their coords, creates boss, second boss and start points into a lookup dictionary (they live outside `Grid`), wires children with `WireChildren`, and refills `startMapPoints` from `StartMapPointCoords`.
- Result: a modded map that is a valid `ActMap` with a grid, a start, a boss and child links round-trips through the save with no extra work, whatever its shape. A save made with the mod still loads without the mod, because `SavedActMap` is a generic container. Quests added through `MapPoint.AddQuest` and `FurCoat` marks are not saved in the map; they are re-applied by Late hooks and `AfterMapGenerated` on each load.
- `RunManager.InitializeSavedRun` (on load) builds `SavedMapsToLoad` from `SerializableRun.Acts[i].SavedMap`, and calls `AfterMapLocationChanged`. Then `NGame.LoadRun` calls `RunManager.Launch`, `NRun.Create`, `GenerateMap` (saved branch, hook fires), then `RunManager.LoadIntoLatestMapCoord(preFinishedRoom)`.
- `RunState.FromSerializable` restores the visited list with `_visitedMapCoords.AddRange(save.VisitedMapCoords)`. The current coord is not stored separately: `RunState.get_CurrentMapCoord` returns the last element of `_visitedMapCoords` or null. `get_CurrentMapPoint` is `Map.GetPoint(CurrentMapCoord)`.
- `LoadIntoLatestMapCoord` calls `EnterMapCoordInternal(VisitedMapCoords[^1], preFinishedRoom, false)` and then `EnterRoomInternal`. If the visited list is empty it enters nothing.
- Visited coords are per act: `SetActInternal` calls `RunState.ClearVisitedMapCoordsDebug` (clears the list and sets ActFloor to 0) right after setting `CurrentActIndex`.
- `RunState.RemoveStaleVisitedMapCoords(map)` does `_visitedMapCoords.RemoveAll(c => !map.HasPoint(c))` and logs an error with the count. If a mod regenerates the map for a run that already has visited coords, those coords are silently dropped and the current coord falls back to an earlier entry or null. `NMapScreen.RecalculateTravelability` also logs "VisitedMapCoord ... not found ... map may have been regenerated" and falls back to the starting point.
- Consequence for a run started before the mod was installed: the saved vanilla map is used for that act (saved branch), so a conversion hooked only on the fresh branch never touches it. A conversion hooked on `AfterMapGenerated` would run on the loaded vanilla map and could renumber coords out from under `VisitedMapCoords`. [inferred: the mod needs a "map already converted" marker, for example a recognisable shape, or must refuse to convert when `VisitedMapCoords` is non-empty.]

## 3. Map classes

- `ActMap`: abstract. Virtual `BossMapPoint`, `StartingMapPoint`, `SecondBossMapPoint`, `Grid` (`MapPoint[,]` indexed `[col,row]`). `GetColumnCount` and `GetRowCount` are `Grid.GetLength(0/1)`. `GetAllMapPoints` and `GetPointsInRow` iterate `Grid` only, so they never return the start, boss or second boss. `GetPoint(col,row)` checks boss, second boss and start coords first, then `Grid` with bounds checks, else null. `HasPoint` and `IsInMap` use the same bounds; `IsInMap` returns true for point types Boss and Ancient without checking the grid.
- `StandardActMap` (vanilla): `Grid` is 7 columns by `ActModel.GetNumberOfRooms(isMultiplayer) + 1` rows. Start is at `(3, 0)`, boss at `(3, RowCount)`, second boss at `(3, RowCount + 1)`. Seven random paths are generated from row 1 with `startMapPoints`; every first-row point is a child of start, every last-grid-row point is a child of boss, and boss gets the second boss as its child when `HasSecondBoss`. Post-processing: `MapPathPruning.PruneAndRepair` (only when `replaceTreasureWithElites` is on, inferred from the branch), `MapPostProcessing.CenterGrid`, `SpreadAdjacentMapPoints`, `StraightenPaths`.
- `GoldenPathActMap` (GoldenCompass relic): precedent for a strict line inside the engine. Grid width 7, a single column 3 filled for rows 1..N, start `(3,0)` typed Ancient, boss typed Boss, each point has exactly one child, last point is the boss's parent, and `startMapPoints` holds the first point. It is built from a fixed `_defaultPointTypes` list and is returned from `GoldenCompass.ModifyGeneratedMap`. It has no `SecondBossMapPoint` override. The engine, `SavedActMap`, travel and the map screen all handle it, so a one-column strict line is a supported shape. [inferred for second boss acts, since GoldenPath does not set a second boss.]
- `SpoilsActMap` (SpoilsMap card, and BigGameHunter in some paths): width 7 hourglass with seven paths converging on a `_treasureRow`; also builds its own start and boss; no second boss override. It ignores the incoming map and generates from scratch with `Rng("spoils_map")`.
- `SavedActMap`: described above. `NullActMap`, `MockCraftedActMap`, `MockSinglePointActMap` are test or placeholder maps and are not constructed by gameplay code (only `NullActMap`'s own static init was found).
- Who constructs which: `SpoilsMap.ModifyGeneratedMap` -> `SpoilsActMap`; `BigGameHunter.ModifyGeneratedMap` -> new `StandardActMap` (and `SpoilsActMap`); `GoldenCompass.ModifyGeneratedMap` -> `GoldenPathActMap`; `GenerateMap` -> `SavedActMap`.

## 4. Dependents on map shape

For each: what reads the map, and what breaks on a strict line. "Break" means breaks if the mod does not take the stated care.

### 4.1 Row index is used as an array index into run history (hard constraint)

- `Runs.RunState.GetHistoryEntryFor(MapLocation)` returns `_mapPointHistory[location.actIndex][location.coord.row]` when `row < list.Count`. Callers: `Multiplayer.Game.RewardSynchronizer.HandleRewardObtainedMessage` and `Nodes.Screens.Map.NMapPoint.OnFocus` (hover info on a point). The history list for an act gets one entry appended per point entered (`RunState.AppendToMapPointHistory` from `EnterMapPointInternal`), starting with the act's start point, which `RunManager+<EnterAct>d__196` enters through `EnterMapCoord(StartingMapPoint.coord)`.
- Break: if two points on the unified path share a row, or rows skip a number, history lookups return the wrong entry (or none), and multiplayer reward messages resolve to the wrong point. Rows must be 0, 1, 2, ... one per step, start at row 0. A snake layout that puts several points on one row (the reference mod does) is incompatible with this. Columns are free. [inferred: the "index equals step number" part, from the append pattern; the indexing by `row` is read directly.]

### 4.2 Floor counters

- `RunManager.EnterMapCoordInternal(coord, ...)` looks up `Map.GetPoint(coord)` and calls `EnterMapPointInternal(actFloor = coord.row + 1, point.PointType, ...)`, which does `RunState.set_ActFloor(actFloor)`. So `ActFloor` is `row + 1`. Readers of `ActFloor`: `NTopBarFloorIcon.UpdateIcon`, `NMapScreen.Open`, `NRewardsScreen.OnProceedButtonPressed`, `ActChangeSynchronizer.MoveToNextAct`, score screen, relic and card commands (stats), AutoSlay. Break: on a strict line with contiguous rows 0..N these numbers are correct; with repeated rows or an offset they show the wrong floor.
- `RunState.get_TotalFloor` sums the per-act sizes of `MapPointHistory`, not rows. It drives `EncounterModel.GenerateMonstersWithSlots` (monster slot RNG), `Events.PunchOff.IsAllowed`, `Events.SlipperyBridge.IsAllowed` and `RelicModel.IsBeforeAct3TreasureChest`. A strict line with the same number of points as the vanilla map keeps these in step. A longer or shorter line shifts the floor thresholds these events and the relic check use. [inferred: the thresholds themselves were not decoded.]
- `Runs.IRunState.CurrentRoomCount` is used by `WingedBoots.AfterRoomEntered`, `EnterRoomInternal`, `ExitCurrentRooms` and `ProceedFromTerminalRewardsScreen`. It is a room counter, not map based.

### 4.3 Travel graph: children, rows and free travel

- `Map.MapTravel.GetTravelablePointsFrom(runState, currentPoint)`: if `Hook.ShouldAllowFreeTravel(runState)` is true it returns `Map.GetPointsInRow(currentPoint.coord.row + 1)`; otherwise it returns `currentPoint.Children`. `WingedBoots.ShouldAllowFreeTravel` is `!IsUsedUp`. Break: with one point per row and contiguous rows, free travel degenerates to the same single next point, so it is harmless. Rows with gaps would make free travel return empty. `WingedBoots.AfterRoomEntered` then checks whether the point entered is in `CurrentMapPoint.Children` of the previous visited point (via `VisitedMapCoords[^2]`) and uses a charge only when it is not; on a strict line every move is a child move, so the relic never spends charges and is dead weight. [inferred for the "never spends" part.]
- `RunManager.EnterMapCoord` does not validate that the coord is a child of the current point. It only calls `RunState.AddVisitedMapCoord` (rejects duplicates, resets `NextRoomId`) and `EnterMapCoordInternal`. Travelability is enforced only on the UI side by `NMapScreen.RecalculateTravelability` through `GetTravelablePointsFrom`. The reference mod patches `GetTravelablePointsFrom` with a prefix returning a custom set.
- `MapPoint` graph helpers that read `Children` and `parents`: `GetFirstCommonDescendant`, `GetCommonAncestor`, `GetLastJunctionLength`, `GetAllDescendants`, `GetAllAncestors`, `BFS_FindPath`, `IsDescendantPathSame`, `LeftChild`, `RightChild`, `IsAdjacentLeft/Right`, `IsToTheLeft/Right`, `IsInTheSameRow`. Their callers are the map pruning and post-processing used while generating `StandardActMap`, the split vote logic, and the AutoSlay map handler. None of the gameplay relics or cards found use them. They only matter if the mod still passes the map through `StandardActMap` post-processing. On a one-child chain they return degenerate but valid values. [inferred: "split vote logic" attribution; the callers listed by the dump are `MapPoint` itself, `MapPathPruning`, `MapPostProcessing`, `SpoilsActMap/StandardActMap.GetSiblings`, `NMapScreen.DrawPaths`, `MapScreenHandler` (AutoSlay), `WingedBoots`, `Pantograph`, `EnterMapPointInternal`.]
- `Runs.RunManager.EnterMapPointInternal` calls `BuildRoomTypeBlacklist(previousEntry, CurrentMapPoint.Children)` for every point. It adds `Shop` to the blacklist when the previous history entry contained a shop room, or when every child is a Shop-typed point (`PointType == 2`). Then `RollRoomTypeFor(pointType, blacklist)` rolls the actual room for Unknown points through `UnknownMapPointOdds.Roll` (which also applies `Hook.ModifyUnknownMapPointRoomTypes`). Break: nothing breaks. On a line each point has exactly one child, so an Unknown directly before a Shop point can never roll a Shop room, and the final boss point is never blacklisted because the IL guards the all-children test with `Count > 0`. No extra handling is needed for adjacent Unknown then Shop in the ordering rules, but they should know that pair yields a non-shop room.

### 4.4 Boss and act end detection

- End of act is detected by coordinate equality with `Map.BossMapPoint.coord` and `Map.SecondBossMapPoint.coord`, in `Combat.CombatManager+<EndCombatInternal>d__120` (before `AchievementsHelper.AfterBossDefeated`) and in `Nodes.Screens.NRewardsScreen.OnProceedButtonPressed` (decides whether to call `RunManager.ProceedFromTerminalRewardsScreen`). `RunManager+<EnterNextAct>d__194` then calls `WinRun` when the current room `IsVictoryRoom` and it is the last act. `Models.Relics.Pantograph.AfterRoomEntered` tests `BossMapPoint.parents.Contains(CurrentMapPoint)`, so it triggers on the point just before the boss. `Nodes.TopBar.NTopBarRoomIcon.UpdateIcon` and `NTopBarBossIcon` compare the current point to `SecondBossMapPoint` to choose boss icons. `Nodes.Screens.Map.NBossMapPoint._Ready` reads `SecondBossMapPoint`.
- Break: the unified path must keep real `BossMapPoint` (and `SecondBossMapPoint` when `HasSecondBoss`) objects at the end, with `Boss -> SecondBoss` as a child link, and the boss coord must be the last row. If the mod stores its own boss object with a different coord, the act never ends. The second boss, if present, is entered after the first boss with no travel choice.
- Pantograph: with one chain, the point immediately before the boss is the only parent; it fires there. Fine.

### 4.5 Start point

- `RunManager+<EnterAct>d__196` calls `NMapScreen.InitMarker(StartingMapPoint.coord)` and `EnterMapCoord(StartingMapPoint.coord)` as soon as the act is set up, so the start counts as the first entered point and the first history entry.
- The start point's type is not always Ancient. `GenerateMap` sets it to Monster when the run did not start with Neow (`ExtraFields.StartedWithNeow` false) and `CurrentActIndex == 0`. The project vocabulary says the path starts at the act's Ancient; for act 1 without Neow the start is a Monster point instead. [Flag for the ordering rules and for CONTEXT.md.]

### 4.6 Map screen layout

- `Nodes.Screens.Map.NMapScreen.SetMap` sizes and positions the screen from `GetRowCount`, `GetColumnCount` and `SecondBossMapPoint`, and places each `GetAllMapPoints` entry at `(col * _distX, row * _distY)` plus seeded jitter (`Rng("map_jitter_" + act index)`), then creates the boss node. `Open` scrolls to the current point using `coord.row * _distY`. `DrawPaths` draws a path per `(parent, child)` pair. Break: a single column of N rows is a tall scroll but valid; GoldenPath shows it is fine. Ticket 03 covers the screen and travel in detail.
- `NMapScreen.RecalculateTravelability` handles a missing last visited coord by falling back to the starting point node.

### 4.7 Map-altering cards, relics and modifiers

- `Models.Cards.SpoilsMap`: `ModifyGeneratedMap` (Early) swaps in `SpoilsActMap` if the card is in the deck pile (checks `SpoilsActIndex` against the act and `Pile.Type`); `ModifyGeneratedMapLate` picks the first point matching a type predicate and stores `SpoilsCoord` (the predicate compares `PointType` to 3, Treasure, per the IL; the lambda dumps run together so this is the best read); `AfterMapGenerated` does `if (map.HasPoint(SpoilsCoord)) map.GetPoint(SpoilsCoord).AddQuest(this)`; `BeforeCardRemoved` removes the quest. `Multiplayer.Game.OneOffSynchronizer+<TryHandleSpoilsMap>d__14` reads the current point's `Quests`. Break: if the mod converts the map after `SpoilsCoord` was chosen, that coord may not exist on the new map and the quest silently never attaches. If the mod converts before the Late hooks, `ModifyGeneratedMapLate` chooses a Treasure point from the unified path, which needs at least one Treasure point.
- `Models.Relics.FurCoat`: `ModifyGeneratedMapLate` and `AfterObtained` call `AddMarkedRooms(map)`, which keeps stored `GetMarkedCoords` if all exist (`TrueForAll(map.HasPoint)`), else picks points from `GetAllMapPoints` filtered by a lambda (the IL shows `PointType == 5` Monster, `CanBeModified`, and no existing quests) shuffled with `Rng(relic id)`, up to the relic's "Combats" count. Break: stored coords that no longer exist cause a re-roll; a line with too few Monster points gives fewer marks.
- `Models.Modifiers.BigGameHunter.ModifyGeneratedMap`: counts Elite points in the incoming map (`GetAllMapPoints` with `PointType == 6`), builds a `MapPointTypeCounts` with a rounded larger elite count and ignore-rules set, and regenerates a new `StandardActMap`. It discards the incoming map. Break: this is an Early hook, so any conversion done earlier than Early hooks is thrown away.
- `Models.Relics.GoldenCompass.ModifyGeneratedMap`: returns `GoldenPathActMap` for the act index stored in `GoldenPathAct`. Early, discards the incoming map. Same ordering issue. `GoldenCompass.AfterObtained` also appears in the `GenerateMap` caller list; it calls `RunManager.GenerateMap` to regenerate mid-run. [inferred: purpose, from the caller list. This means a relic pick can trigger a fresh-branch regeneration while `VisitedMapCoords` is non-empty; `RemoveStaleVisitedMapCoords` then prunes. Worth a ticket.]
- `Models.Relics.Pantograph`, `WingedBoots`: covered above.
- `GameActions.MoveToMapCoordAction` and `VoteForMapCoordAction`, `MapSelectionSynchronizer`, `MapVote`: multiplayer. A vote is a `MapCoord` plus `mapGenerationCount`. With one child there is one option, but the player still has to click the next point unless the mod auto-travels. `Nodes.Screens.Map.NMapScreen.OnMapPointSelectedLocally` enqueues `VoteForMapCoordAction`. `MapSelectionSynchronizer.BeforeMapGenerated` cancels votes whose `mapGenerationCount` is old.

### 4.8 Combat and room generation

- `Combat.CombatState.CreateCreature` seeds each monster `Rng` from run seed, `CurrentMapCoord.col`, `CurrentMapCoord.row`, `CurrentActIndex` and the creature's `CombatId`. Break: nothing breaks, but the same seed produces different monster rolls (unique HP values) once coords change. Unique coords per point keep the seeds distinct. If every point uses column 3, the `col` term stops varying; row still varies.
- `Runs.RunManager.CreateRoom(roomType, mapPointType, ...)` pulls encounters with `ActModel.PullNextEncounter(roomType)` (from `RoomSet.NextNormalEncounter / NextEliteEncounter / NextBossEncounter`), events with `PullNextEvent`, ancients with `PullAncient`. Rooms are not tied to coordinates. They are consumed in sequence as points are entered. `ActModel.GenerateRooms` sizes the sets from `GetNumberOfRooms`; `ActModel.GetNumberOfFloors` is `GetNumberOfRooms`. Break: if the unified path has a different number of Monster, Elite or Unknown points than the pools were sized for, `PullNext*` may run out or leave leftovers. The pool sizing (ticket 04) must match the point-type counts. [inferred: exhaustion behavior was not read.]
- `Rooms.IRoomWithProceedButton.GenerateBackgroundRngForCurrentPoint` reads `CurrentMapCoord.row` (and probably col) for the background seed. Cosmetic.
- `ActModel.GetMapPointTypes(isMultiplayer, rng)` (Overgrowth, Hive, Glory, Underdocks, DeprecatedAct) returns the `MapPointTypeCounts` per act: elites, shops, unknowns, rests, using `Rng.NextGaussianInt` and `MapPointTypeCounts.StandardRandomUnknownCount`. This is where the vanilla totals come from; ticket 01 owns the numbers.

### 4.9 Things that do not matter for the mod

- `StandardActMap`/`SpoilsActMap` generators and `MapPathPruning`, `MapPostProcessing`: used only during construction.
- AutoSlay (`AutoSlayer`, `MapScreenHandler`): test automation; reads `Children` and `BossMapPoint`.
- `MapPointHistoryEntry` and `PlayerMapPointHistoryEntry`: store a point type and rooms per entered point, not coordinates. Run history screens read these.

## 5. Where a mod can safely cut in

All of this is read from the call order; the recommendation itself is [inferred].

- Early hooks (GoldenCompass, SpoilsMap, BigGameHunter) replace the map outright. A conversion done before them is discarded. So convert after `Hook.ModifyGeneratedMap` has run the Early hooks.
- Late hooks (SpoilsMap, FurCoat) decorate the map and run on both branches. To give them real points on the unified path, convert before Late hooks run on the fresh branch.
- Option A, postfix `Hook.AfterMapGenerated` (reference mod's seam): runs after Early and Late on both branches, mutates in place, runs again on load against the saved line, so it must detect "already converted". Late hooks see the vanilla shape on the fresh branch and their coords may not survive the rewrite. Cannot swap the map object.
- Option B, prefix on `Hook.ModifyGeneratedMapLate`: on the fresh branch it runs once after all Early hooks and before any Late hook, so Late hooks and `AfterMapGenerated` see the unified path. It can return a new map object. On the saved branch it runs again on an already converted `SavedActMap`, so it must be a no-op there (detect by shape).
- Option C, postfix `Hook.ModifyGeneratedMap` (fresh branch only): the Late hooks have already run on the vanilla shape inside this call, so `SpoilsCoord` and FurCoat marks need re-deriving. Load needs no work because `SavedActMap` already carries the line, but `Late` runs again against it and `AfterMapGenerated` fires normally.
- Whatever the seam, the conversion must also leave: unique contiguous rows from 0 to N, `StartingMapPoint` at row 0, `BossMapPoint` at the last row with a single parent chain, `SecondBossMapPoint` after it when present, `Grid` dimensions that contain every non-boundary point, `startMapPoints` filled (needed only for the save field), `Children`/`parents` kept consistent (use `AddChildPoint` and `RemoveChildPoint`), and `CanBeModified` set sensibly on points that FurCoat may mark.
