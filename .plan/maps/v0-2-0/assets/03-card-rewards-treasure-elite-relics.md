# Card rewards, treasure chests, and Elite relics: how the game builds them

Source: `references/decompiled-v0.107.1/` (game v0.107.1). Paths below are relative to that folder. `references/decompiled/sts2.txt` (the installed build's signatures) matches every signature quoted here. One test run used v0.111.0 public beta, which is not decompiled; see "Version risk" at the end.

## 1. How combat rewards are built

- `MegaCrit.Sts2.Core.Rewards/RewardsSet.cs`. `CombatRoom.OfferRoomEndRewards()` (`MegaCrit.Sts2.Core.Rooms/CombatRoom.cs`) calls `RewardsCmd.GenerateForRoomEnd(player, room)` per player (`MegaCrit.Sts2.Core.Commands/RewardsCmd.cs`). That runs `new RewardsSet(player).WithRewardsFromRoom(room)` then `GenerateWithoutOffering()`, and `Offer()` shows the screen.
- `WithRewardsFromRoom` calls the private `RewardsSet.GenerateRewardsFor(Player, AbstractRoom)` and appends `CombatRoom.ExtraRewards` (cards such as The Hunt add to those).
- `GenerateRewardsFor` is a switch on `room.RoomType`:
  - `Monster`: `GoldReward(min*GoldProportion, max*GoldProportion)` if `GoldProportion > 0`, then `RollForPotionAndAddTo` (`PotionRewardOdds.Roll`), then `new CardReward(CardCreationOptions.ForRoom(player, room.RoomType), 3, player)`.
  - `Elite`: `GoldReward`, potion roll, `CardReward(..., 3, ...)`, `new RelicReward(player)`.
  - `Boss`: `GoldReward`, potion roll, `CardReward(..., 3, ...)`. (Last boss of the last act returns an empty set earlier in `WithRewardsFromRoom`.)
- `GenerateWithoutOffering` then calls `reward.Populate()` on every reward (this is where RNG is consumed), then `Hook.ModifyRewards` (`Hook.cs`: all `TryModifyRewards`, then all `TryModifyRewardsLate`), populates any rewards the hooks added, and sorts by `Reward.RewardsSetIndex` (Gold 1, Relic 3, Card 5).
- Combats that come out of Unknown points: `RunManager.RollRoomTypeFor` calls `RunOddsSet.UnknownMapPoint.Roll` (`MegaCrit.Sts2.Core.Odds/UnknownMapPointOdds.cs`), which returns a `RoomType`. A combat result is `RoomType.Monster` (Elite odds are -1 in vanilla, so Unknown never gives an Elite). So an Unknown combat is an ordinary `CombatRoom` with `RoomType.Monster` and goes through the same `case RoomType.Monster` branch. A mod cannot tell it apart from a Monster point by `RoomType`; use the map point type (`MapPointType.Unknown`) from `MapPointHistory` if it ever needs to.

## 2. Card choice count (3 vs 4)

- The count is a constructor argument: `CardReward(CardCreationOptions options, int cardCount, Player player, PlayerChoiceSynchronizer? synchronizer = null)` in `Rewards/CardReward.cs`. It is stored in the private `OptionCount` and used by `CardReward.Populate()` -> `CardFactory.CreateForReward(Player, int cardCount, CardCreationOptions)` (`MegaCrit.Sts2.Core.Factories/CardFactory.cs`), which loops `cardCount` times, blacklisting duplicates, rolling rarity, picking a card from `Player.PlayerRng.Rewards`, and rolling an upgrade.
- There is no hook, setting, or per-player property for the count. The literal `3` is hard coded at each call site: `RewardsSet.GenerateRewardsFor` (Monster, Elite, Boss), and also `PrayerWheel`, `WhiteStar`, `Orrery`, `LostCoffer`, `GlassEye` (relics), events `Trial`, `BrainLeech`, `TheFutureOfPotions`, `ColorfulPhilosophers` (uses a dynamic var), the `Draft` modifier, `TheHunt` (card), `CrystalSphereCardReward`, and `DreamCatcher` (rest site). Saved rewards rebuild with `save.OptionCount` (`Reward.cs` FromSerializable), so a saved 4 stays 4 on reload.
- Yes, a mod can show 4. Cleanest hook: a Harmony Prefix on the `CardReward` constructor `(CardCreationOptions, int, Player, PlayerChoiceSynchronizer)` with `ref int cardCount`, changing 3 to 4 when `WayfinderConfig` says so. That covers combat rewards, Prayer Wheel, White Star, and the Hunt in one patch. Decide whether events and relics that grant "pick 1 of 3" (Orrery, Lost Coffer, Glass Eye, Trial, etc.) should also become 4. If not, restrict the patch by checking `options.Source == CardCreationSource.Encounter` (set by `CardCreationOptions.ForRoom` for Monster/Elite/Boss rooms; other callers use `Other`). The second constructor `(IEnumerable<CardModel>, CardCreationSource, Player, CardCreationOptions)` takes a fixed list (tutorial and Kaleidoscope) and should be left alone.
- UI fits: `NCardRewardSelectionScreen` (`MegaCrit.Sts2.Core.Nodes.Screens.CardSelection/`) lays the row out from `_options.Count` (centered, 350 px spacing), so any count works. Lasting Candy already produces 4 cards on some combats. A check of 4 cards at the lowest supported resolution is still a playtest item.
- Alternative: Harmony Postfix on `CardFactory.CreateForReward(Player, int, CardCreationOptions)` to raise the `cardCount` argument. Not recommended: it hits shops-adjacent and event paths that the constructor patch can scope more cleanly.

## 3. Skipping the card reward on some normal combats, keeping gold and potions

- Where: the `Monster` branch of `RewardsSet.GenerateRewardsFor` builds the list in order gold, potion, card. Removing the `CardReward` after that method returns keeps the other two intact.
- Patch: Harmony Postfix on the private `RewardsSet.GenerateRewardsFor(Player player, AbstractRoom room)` (instance method, `List<Reward>` result). If `room.RoomType == RoomType.Monster` and this is a "no reward" combat, `__result.RemoveAll(r => r is CardReward)`. `Populate` has not run yet, so the removed reward consumes no RNG and the potion roll (done before) is unaffected.
- Relics that add their own card reward later: `PrayerWheel.TryModifyRewards` adds an extra `CardReward` to every `RoomType.Monster` room; `Elite`/`Boss` extras (`WhiteStar`, `LavaRock`) do not touch Monster rooms. If the mod wants "no reward" to mean no card reward at all, also Postfix `Hook.ModifyRewards(IRunState, Player, List<Reward>, AbstractRoom)` and strip `CardReward` there for the flagged room, or accept that Prayer Wheel still pays out (it is a Rare relic, so this is arguably intended). Decide this in the build ticket.
- Empty-reward combats work: `RewardsSet.Offer` still shows the rewards screen for a `CombatRoom` even with zero rewards (`flag = Room is CombatRoom` skips the early return), and `Encounter.ShouldGiveRewards` is a separate per-encounter switch, so no UI patch is needed.
- Alternation state ("reward, none, reward, ..." for normal combats including Unknown combats, starting with a reward): no new save field is needed. Count prior Monster-type combats from run history the same way the game's tutorial code does: `player.RunState.MapPointHistory.SelectMany(l => l)` and count entries whose `Rooms` contain a `MapPointRoomHistoryEntry` with `RoomType == RoomType.Monster` (see `RewardsSet.TryGenerateTutorialRewards`, which counts `MapPointHistoryEntry.Rooms.FindIndex(r => r.RoomType == RoomType.Monster)`). The entry for the current room already exists while rewards are generated, which is why the tutorial uses `num - 1` as the zero-based index; verify this off-by-one in a test before relying on it. Unknown points that rolled a Monster appear with `RoomType.Monster` in `Rooms`, so they count automatically. Event or shop Unknowns do not.
- Multiplayer: the alternation must be the same for every player, so key it on the room/run history (shared), not on a per-player counter.
- Potions: `PotionRewardOdds.Roll(player, ascensionManager, roomType)` (`Odds/PotionRewardOdds.cs`) mutates odds on each roll and is called regardless of the card branch, so potion odds stay vanilla.

## 4. Treasure chest contents (relic and gold)

- `MegaCrit.Sts2.Core.Rooms/TreasureRoom.cs`. Treasure does not go through `RewardsSet.GenerateRewardsFor`; its `else if (room is TreasureRoom)` case just returns an empty list.
- Relic: `TreasureRoom.EnterInternal` calls `RunManager.Instance.TreasureRoomRelicSynchronizer.BeginRelicPicking()` (`MegaCrit.Sts2.Core.Multiplayer.Game/TreasureRoomRelicSynchronizer.cs`) as soon as the room is entered. For each player where `Hook.ShouldGenerateTreasure(runState, player)` is true it does `RelicFactory.RollRarity(_rng)` (`_rng` = `RunState.Rng.TreasureRoomRelics`) then `_sharedGrabBag.PullFromFront(rarity, runState)` on `RunState.SharedRelicGrabBag`, falling back to `RelicFactory.FallbackRelic` (Circlet). The results go in `CurrentRelics`. The first-ever run forces `Gorget` via `TryGetRelicForTutorial`. With zero relics, `EndRelicVoting()` nulls `CurrentRelics`.
- Gold: the player opens the chest in `NTreasureRoom.OpenChest()` which calls `TreasureRoom.DoNormalRewards()` -> `OneOffSynchronizer.DoLocalTreasureRoomRewards()` -> private `OneOffSynchronizer.DoTreasureRoomRewards(Player)` (`Multiplayer.Game/OneOffSynchronizer.cs`). It returns 0 if `!Hook.ShouldGenerateTreasure`, otherwise `gold = player.PlayerRng.Rewards.NextInt(42, 53)` (42 to 52), times `AscensionHelper.PovertyAscensionGoldMultiplier` at Poverty, then `PlayerCmd.GainGold`, then `TryHandleSpoilsMap`. It runs on every peer (`HandleTreasureChestOpenedMessage` for remote players), so patches here must be deterministic.
- Empty chests are already supported by the UI: `NTreasureRoomRelicCollection.InitializeRelics()` (`Nodes.Screens.TreasureRoomRelic/`) sets `_isEmptyChest` and plays `SpawnEmptyChestVfx` when `CurrentRelics` is null or empty, and `CompleteWithNoRelics()` finishes the vote. Silver Crucible (`Models.Relics/SilverCrucible.cs`) does this on the first chest via `ShouldGenerateTreasure`.
- Replacing with a seeded outcome table (relic with small gold, big gold with no relic, etc.):
  - Roll the outcome once per treasure room. Best place: Harmony Prefix or Postfix on `TreasureRoomRelicSynchronizer.BeginRelicPicking()`. It runs on every peer at room entry, before the chest is opened, and already owns a seeded stream.
  - Stream: `RunState.Rng.TreasureRoomRelics` (`RunRngType.TreasureRoomRelics`). It is saved and restored by counter (`RunRngSet.ToSerializable/FromSave`). It is only used here, for the rarity roll, for MP vote filling, and for MP relic fights, so an extra draw per chest is deterministic. Reach it through the synchronizer's private `_rng` field (use `AccessTools.Field`) or `RunManager.Instance.State.Rng.TreasureRoomRelics`.
  - "No relic" outcome: let `BeginRelicPicking` run with a Prefix that returns false after setting `_currentRelics` to an empty list via reflection, or simpler, make `Hook.ShouldGenerateTreasure` return false for relic only. Note `ShouldGenerateTreasure` is shared: `Hook.ShouldGenerateTreasure` gates both the relic in `BeginRelicPicking` and the gold in `DoTreasureRoomRewards`, so a Postfix on it cannot split them. Patch the two call sites instead, or patch the two methods directly.
  - Relic rarity for the "relic" outcome: keep `RelicFactory.RollRarity(Rng)`, or pass your own rarity to `_sharedGrabBag.PullFromFront(RelicRarity, IRunState)`. The shared bag handles rarity fall-through (Shop -> Common -> Uncommon -> Rare) and removal.
  - Gold amounts: Postfix or Prefix on `OneOffSynchronizer.DoTreasureRoomRewards(Player)` (private, returns `Task<int>`). The vanilla draw uses `player.PlayerRng.Rewards`, shared with card, gold, and potion rolls. If the mod replaces the draw, it should either still make the vanilla `NextInt(42, 53)` call (to keep that stream's counter aligned with vanilla runs) or take the amount from the table roll on `TreasureRoomRelics` so the player stream is not disturbed. Pass the room's chosen outcome from the roll to the gold step through a static keyed by the current map coord; `RunState.CurrentMapCoord` is available.
  - Spoils Map gold (`TryHandleSpoilsMap`) is added after and is unaffected.
- Mod's existing hook: `Act3RelicCheckPatch` patches `RelicModel.IsBeforeAct3TreasureChest` (floor 41 singleplayer, 38 MP). That guard (`WhiteStar`, `LastingCandy` `IsAllowed`) is unrelated to chest contents but is the only chest-adjacent patch in `sts2_wayfinder_modCode/UnifiedPath/Act3RelicCheckPatch.cs`.

## 5. Elite relic rarity

- Elite: `GenerateRewardsFor` adds `new RelicReward(player)` (`Rewards/RelicReward.cs`), whose rarity field is `RelicRarity.None`. `RelicReward.Populate()` then calls `RelicFactory.PullNextRelicFromFront(Player)` (or the `Rng` overload when `_rngOverride` is set) in `MegaCrit.Sts2.Core.Factories/RelicFactory.cs`.
- That calls `RelicFactory.RollRarity(Player)` -> `RollRarity(player.PlayerRng.Rewards)`: one `rng.NextFloat()`; `< 0.5` Common, `< 0.83` Uncommon, else Rare. So vanilla is 50% Common, 33% Uncommon, 17% Rare. Then `player.RelicGrabBag.PullFromFront(rarity, filter, runState)` takes the next relic in that rarity's pre-shuffled deque (shuffled once at run start from `RunRngType.UpFront`), removes it from the shared bag too, and falls back through rarities then `Circlet`.
- `RollRarity(Player)` is also used by the Shop (`PullNextRelicFromBack(Player)`), and `RelicReward(player)` is also built by events (`WarHistorianRepy`, `PunchOff`), `SmallCapsule`, `Vintage` modifier, and `BlackStar` (extra Elite relic). Patching `RollRarity` globally would shift those too.
- Ways to shift toward Common while keeping RNG parity:
  1. Scoped: Harmony Postfix on `RewardsSet.GenerateRewardsFor` (same patch as the card skip) that, for `RoomType.Elite`, replaces the vanilla `RelicReward(player)` with `new RelicReward(rarity, player)` (the `RelicReward(RelicRarity, Player)` constructor exists; `Populate` then calls `PullNextRelicFromFront(Player, rarity)`). Choose `rarity` with your own thresholds (for example Common < 0.75, Uncommon < 0.95, else Rare) from a stream. To stay in sync with save/load, draw one float from `player.PlayerRng.Rewards` (same single draw vanilla makes) at that moment and map it with the new thresholds. Because `Populate` has not run yet, the vanilla draw never happens, so total consumption is unchanged.
  2. Global: Postfix or transpiler on `RelicFactory.RollRarity(Rng)` (single float read; thresholds 0.5f and 0.83f are literals). This also changes treasure chests (they call `RollRarity(Rng)` with `TreasureRoomRelics`), Elite, events, and shops, so it conflicts with the map's decisions that chests use their own table and event and shop relics stay vanilla.
  3. Black Star: its extra Elite relic comes from `Hook.ModifyRewards` as another bare `RelicReward(player)`. To shift it too, Postfix `Hook.ModifyRewards` and swap any bare `RelicReward` for rarity-bearing ones. A check: the `Rarity` property on `RelicReward` is `_rarity` (None for bare), so detect by `reward is RelicReward r && r.Rarity == RelicRarity.None && r.Relic == null`.
- Relic pools are finite per rarity; `RelicGrabBag.GetAvailableDeque` falls upward (Common -> Uncommon -> Rare) when a deque is empty (`_refreshAllowed` can refill it). Shifting every Elite toward Common will empty Common early in a long Wayfinder run (more Elites per run than vanilla), so the Common deque falls through to Uncommon and Rare later. Worth a note in the build ticket and in playtests.

## 6. Seeded RNG streams to reuse

All are `MegaCrit.Sts2.Core.Random.Rng` (counter-based, saved by counter so save/load is deterministic).

| Stream | Where | Used for |
|---|---|---|
| `Player.PlayerRng.Rewards` (`PlayerRngType.Rewards`, `Random/PlayerRngSet.cs`) | per player | gold amounts (`GoldReward.Populate`), potion reward rolls, card rarity and card picks and upgrades (`CardFactory.CreateForReward`), Elite relic rarity (`RollRarity(Player)`), chest gold (`NextInt(42, 53)`) |
| `RunState.Rng.TreasureRoomRelics` (`RunRngType.TreasureRoomRelics`, `Runs/RunRngSet.cs`) | per run | chest relic rarity roll, MP vote fill and relic fight moves |
| `RunState.Rng.UpFront` | per run | shuffles relic deques at run start; do not draw from it mid-run |
| `RunState.Rng.UnknownMapPoint` | per run | Unknown point room type roll |
| `RunState.Rng.Niche` | per run | "niche one-off" rolls that must not interfere with anything else |
| `Player.PlayerRng.Shops` / `Transformations` | per player | shops, transforms; not relevant here |

- Each `Rng` is seeded from the run seed plus a snake-cased name, e.g. `new Rng(seed, "treasure_room_relics")` (`Random/Rng.cs`). Another constructor `Rng(Player, ModelId, uint mixin, int counter)` makes per-content streams keyed by seed, player slot, and content id.
- Recommended for new mod streams (outcome table roll, anything the mod adds): use `RunState.Rng.TreasureRoomRelics` for chest outcome, and keep gold amount on `PlayerRng.Rewards` if you want vanilla alignment. For anything with no natural game stream, the mod already has `Ordering/SeededOrderingRng.cs` (FNV hash of the seed text and a name; no game RNG type). Caveat: it is not saved by counter, so it is only safe if the draws are a pure function of state (for example hash seed plus map coordinate), not a running sequence across a save/load.
- Taking any stream through the game's `Rng` type is risky across versions: the mod's own comment in `SeededOrderingRng` says the numeric seed is `uint` on stable and `ulong` on public-beta. Use `Rng` instances the game already created and call `NextFloat()` / `NextInt(...)`, do not construct `new Rng(seed, name)` yourself.

## 7. Relics and cards that change card choice count or chest contents

Choice count. No relic or card changes the number of choices through a hook (there is no hook for it). The ones that change what a reward shows:
- `Lasting Candy` (`Models.Relics/LastingCandy.cs`, `TryModifyCardRewardOptions`): appends an extra Power card to combat card rewards on some combats (`creationOptions.Source == Encounter`, `IsInTriggeringCombat`). With the mod's 4-choice change this gives 5. It is added after the count, so it simply stacks.
- `Prayer Wheel` (extra Monster card reward, count 3 literal), `White Star` (extra Boss-odds card reward on Elite, 3), `Orrery`, `Lost Coffer`, `Glass Eye`, `The Hunt`, `Dream Catcher` (rest site): each builds its own `CardReward` with `3`; they follow the constructor patch if it is unscoped.
- `Black Star` adds a second Elite `RelicReward`. `Lava Rock` adds a Boss relic reward.
- Card-pool and card-content modifiers (no count effect): `Dingy Rug` (adds colorless pool via `ModifyCardRewardCreationOptions`), `Prismatic Gem`, `Frozen Egg`/`Molten Egg`/`Toxic Egg` (upgrade by type), `Silver Crucible` (upgrades the first three rewards and later empties the first chest), `Glitter` (enchant), `Lava Lamp`, `Wing Charm`, `Silken Tress`, `Driftwood` (sets `CanReroll` on every `CardReward`; with 4 choices this is just a reroll of 4).
- Modifier: `Draft` builds its own `CardReward` with 3.

Chest contents. `Hook.ShouldGenerateTreasure` (`AbstractModel.ShouldGenerateTreasure`) is overridden only by `Silver Crucible` (returns false for the owner on the first treasure room entered; `TreasureRoomsEntered > 1` required). With the mod's chest table, Silver Crucible's skip must still be honoured: if `ShouldGenerateTreasure` is false, the mod should roll no table outcome at all. Do the table roll only inside the `if (Hook.ShouldGenerateTreasure(...))` branch (patch after that check). `Spoils Map` adds gold after the chest (`TryHandleSpoilsMap`) and combines additively. `TreasureRoom.DoExtraRewardsIfNeeded` runs `RewardsCmd.GenerateForRoomEnd` for the treasure room, so any relic that implements `TryModifyRewards` for `RoomType.Treasure` would add extras there; none in v0.107.1 does (the only `TryModifyRewards` overriders are `PrayerWheel`, `BlackStar`, `WhiteStar`, `LavaRock`, plus modifiers `Vintage`, `Midas`, and a few others that check room type).

How they combine with the mod: card count patch is independent of relics; Prayer Wheel and White Star get 4 as well unless the patch is scoped. Alternating "no reward" combats also skip Lasting Candy's Power card, because it lives inside the card reward. Elite relic rarity shift plus Black Star gives two Common-biased relics. Treasure outcomes must respect Silver Crucible.

## 8. Version risk (stable v0.107.1 decompile vs v0.111.0 public beta)

- Not verifiable here: the v0.111 build was not decompiled. Check before shipping by re-decompiling and diffing these members: `RewardsSet.GenerateRewardsFor`, `CardReward..ctor(CardCreationOptions, int, Player, PlayerChoiceSynchronizer)`, `RelicFactory.RollRarity(Player/Rng)`, `RelicReward..ctor(RelicRarity, Player)`, `TreasureRoomRelicSynchronizer.BeginRelicPicking`, `OneOffSynchronizer.DoTreasureRoomRewards`, `Hook.ShouldGenerateTreasure`.
- Known difference from the mod's own notes: Rng seed type is `uint` on stable and `ulong` on public-beta. Any patch signature that names `Rng(seed, ...)` or `RunRngSet.Seed` types will differ; avoid naming those.
- `GenerateRewardsFor` and `DoTreasureRoomRewards` are private; use `AccessTools.Method` with explicit parameter types and log an error and skip the patch (as `ExtendEncounterListPatch` does) if lookup fails.
- Tuning literals (3 cards, 0.5/0.83 relic thresholds, 42 to 52 gold) are inline constants and may change between builds; patch around them (replacing the reward object or the result) rather than editing IL where possible.
